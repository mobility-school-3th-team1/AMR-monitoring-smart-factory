- `jwt.secret` 커밋 사건
    - 코파일럿 통해 백엔드 security 클래스 구현 중 `application.yaml`에 `jwt.secret`이 포함되었는데 그게 원격에 함께 커밋됨
        - `jwt.secret`이란 로그인 로직 중 암호화/복호화 키로 사용되는 값
    - 코파일럿 리뷰에서 발견되어 `application.yaml`을 로컬용과 테스트용으로 추가 분리하고, 그 두 파일에만 `jwt.secret` 저장, 두 파일은 gitignore되어 원격에 업로드되지 않게 함.
- 코파일럿 리뷰 거부 사건
    - 프론트엔드 작업 후 push, PR 올리고 코파일럿 리뷰 요청했는데, 변경된 파일이 300개를 넘는다고 리뷰 거부당함
    - 첫 번째 원인으로, 프론트엔드 작업 분량 커밋 전 dev로부터 merge를 받았다는 점을 의심하고 merge 기록을 지워 다시 리뷰를 요청했지만 같은 사유로 리뷰를 거부당함
    - 그 후 변경된 파일의 목록(711개)을 확인하던 중 `node_modules`가 커밋에 포함된 것이 확인됨. 이건 커밋에 올리지 않는 폴더이므로 ignore 누락이 문제였음.
    - → 로컬에서 굳이 폴더를 삭제할 필요는 없고, git의 추적을 해제하면 된다 (Gemini가 알려줌)
    - 해결 과정은 다음과 같다
        1. `git rm -r --cached node_modules` 실행
        2. 그 상태 그대로 커밋 후 푸시: `status` 확인은 해도 되지만 `add`는 하면 안됨. 원래대로 돌아가버림.
        3. 원격에서 폴더가 사라졌는지 확인 → 사라졌으면 성공, PR에서 다시 리뷰 요청하면 됨
    - 해결 후 업데이트된 폴더 갯수는 49개로 줄어 있었음
    - 영향:
        - node_modules가 커밋에 올라갔던 기록은 유지된다. 그것도 삭제하려면 별도 툴 필요.
        - 원격에서 확인할 수 있는 폴더 중엔 node_modules가 없게 된다. 처음부터 추적하지 않은 것처럼 됨.
    - 이번 문제는 적어도 하나의 PR에 포함된 변경사항의 범위 내에서 발생한 일이었기 때문에 단순 트래킹 해제로 해결 가능했음.
- DB 스키마와 백엔드 불일치

    - 기능 요구사항을 충족하는 게 우선이기 때문에 백엔드를 기준으로 DB 스키마가 수정됨
