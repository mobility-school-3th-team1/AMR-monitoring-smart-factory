# 1. AI 활용 목적

프로젝트 운영 관점에서 AI를 다음 목적으로 활용하였다.

- **도메인·요구사항 정립 가속**: AMR 사고·운영 리스크 등 제조 현장 맥락 조사를 AI로 보조하고, 프로젝트 배경·페인포인트·가치 제안·고도화 비전의 근거를 빠르게 수집·정리한다.
- **다층 아키텍처 설계 부담 완화**: FE/BE/DB/DAS가 분리된 통합 관제 시스템에서 REST API 계층 구조, API·ERD·화면 설계 등 반복적인 설계 산출물의 초안을 AI로 작성하고, 팀이 검토·정합하는 데 집중할 시간을 확보한다.
- **문서 선행(Design-first) 개발 지원**: `docs/` 명세를 기준으로 구현할 때, TODO 분해·진행도 관리·설계 정합성 검토를 AI에 맡겨 "명세 → 구현" 흐름을 체계적으로 유지한다.
- **멀티 스택 구현 생산성 확보**: Vue, Spring Boot, MySQL 스키마, Node-RED 등 역할별 코드 작성을 Copilot·Cursor로 보조하고, 제한된 일정 안에서 FE·BE·DB를 병행 개발한다.
- **팀 단위 AI 활용 표준화**: `AGENTS.md`·영역별 `TODO.md`로 AI 사용 방식을 공유해, 도구·담당자가 달라도 비슷한 품질과 절차로 개발·리뷰가 이루어지게 한다.
- **품질·보안 리스크의 2차 점검**: AI 생성 코드·설정을 그대로 반영하지 않고, PR 단위 Copilot 리뷰와 팀 검토로 민감 정보 유출·대량 변경·스키마 불일치 등을 사전에 걸러낸다.

# 2. AI 활용 워크플로우

프로젝트 전반에서 반복된 흐름은 다음과 같다.

1. **조사·기획 (Gemini, ChatGPT)**: AMR·스마트팩토리 도메인 자료 조사, 배경·페인포인트·비전 초안
2. **설계 초안 (ChatGPT, Cursor)**: API·ERD·화면 설계, Spring Boot 계층 구조, ADR 초안
3. **팀 확정**: AI 출력을 발췌·재서술하여 `docs/`·GitHub에 반영 (Confluence는 동기화 복사본)
4. **정합성 검토 (Cursor 등)**: 확정 설계 문서를 AI에 재입력해 API·ERD·화면·ADR 간 불일치 점검
5. **구현 (Copilot, Cursor)**: `AGENTS.md`·영역별 `TODO.md`·설계 문서를 컨텍스트로 코드 작성
6. **병합 전 검증**: 로컬 실행·스모크 확인 후 PR 생성
7. **PR 리뷰 (Copilot + 팀)**: Copilot Review 코멘트 검토, 수용·거부는 팀원이 최종 결정

도구별 역할 분담 원칙:

- **Gemini**: 외부 자료·논문·기사 조사, 프로젝트 구조·Git 등 운영 질문 보조
- **ChatGPT**: 기능·API 문장, 발표·보고 초안 등 **문서·설명** 중심
- **GitHub Copilot**: FE/BE/DB **코드 생성**, PR **자동 코드 리뷰**
- **Cursor**: 저장소 전체·`AGENTS.md`를 읽는 **BE 구현·설계 정합성 대화형 검토**
- **DeepWiki(Devin)**: 최종 문서 통합 위키 생성 (예정, 수정 불가한 툴이기 때문에 검토 X)

### 도구별 보충 설명

**ChatGPT**

- 화면 설계서의 SCR 단위 요구를 API 엔드포인트 목록·요청/응답 JSON 형태로 옮기는 초안 작성에 활용하였다.
- 코드 실행·저장소 전체 정합 검증은 하지 않으며, 확정은 Cursor·Copilot·팀 검토로 이관하였다.

**Gemini**

- "AMR 사고", "MES 연동", "공장 관제" 등 키워드로 조사한 논문·기사 요약을 프로젝트 배경·페인포인트 작성의 재료로 사용하였다.
- `시행착오.md`에 기록된 `git rm --cached node_modules` 등 Git 운영 이슈 해결 힌트에도 참고하였다.

**GitHub Copilot**

- `AGENTS.md`에 정의된 패키지 구조·네이밍·API 경로 규칙을 반영한 코드 제안을 받았다.
- 협업 컨벤션에 따라 PR 생성 시 Copilot Review가 자동 요청되며, jwt.secret 원격 커밋·과다 변경 파일 등을 코멘트로 받았다.

**Cursor AI**

- `BE/AGENTS.md`와 `docs/API 정의.md`, `docs/데이터 스키마 설계.md`를 함께 제공하여 BE 레이어 구현·Phase 단위 작업을 진행하였다.
- 설계 문서를 통째로 입력해 API §·ERD 테이블·화면 SCR 번호 간 불일치를 질의·수정하는 데 사용하였다.

**DeepWiki(Devin) (예정)**

- 완성된 레포지토리를 인덱싱하여 위키로 제공하는 서비스
- 최종 문서 통합 위키 생성 (예정, 수정 불가한 툴이기 때문에 검토 X)

# 5. 검증 및 보완 과정

## 5.1 설계 단계

| 단계 | 내용 | 담당 |
| --- | --- | --- |
| 1. AI 초안 | 조사·API·ERD·화면·ADR 초안 생성 | AI |
| 2. 팀 확정 | 발췌·재서술 후 `docs/`·GitHub에 반영 | 팀원 |
| 3. 정합성 검토 | 확정 문서를 AI에 재입력, API·ERD·SCR·ADR 교차 확인 | AI + 팀 |
| 4. 변경 기록 | 스택·경계 변경 시 ADR 작성 (`docs/ADR/`) | 팀 |

- AI가 생성한 문장·표를 **그대로 커밋하지 않고**, 팀원이 직접 발췌·재서술한 내용만 명세에 남긴다.
- 설계 변경 시 관련 문서를 전수 검토하여 API·화면·스키마·ADR을 함께 맞춘다.

## 5.2 개발 단계

| 단계 | 내용 |
| --- | --- |
| 컨텍스트 제공 | 해당 영역 `AGENTS.md` + `TODO.md` + 관련 `docs/` 경로를 AI에 명시 |
| 구현 순서 | `TODO.md` 한 항목씩 진행 (동시 다발 구현 지양) |
| 로컬 검증 | PR 전 정합성·실행 확인 (BE: Docker·H2 스모크 등) |
| PR | `.github/pull_request_template.md` 작성 → Copilot Review → 팀 리뷰·approve → dev merge (merge commit) |

- `AGENTS.md`로 AI 생성물의 **재현 가능한 절차**를 팀 공통 규칙으로 고정하였다.
- Copilot 코멘트는 참고용이며, 수용·거부·수정은 **팀원이 최종 결정**한다.

## 5.3 품질·보안 점검

- 시크릿·`application.yaml` 값은 원격 저장소에 포함하지 않는다.
- `.gitignore` 누락으로 `node_modules` 등 대용량·의존 폴더가 추적되지 않도록 PR 전 diff 범위를 확인한다.
- DB·BE·API 3자 정합이 어긋나면 **기능·API 명세를 우선**하여 스키마·엔티티를 맞춘다.

## 5.4 AI에 맡기지 않은 것

- 최종 요구사항·시연 시나리오·일정 우선순위 확정 (Jira WBS)
- PR merge 승인 및 main/dev 정책 결정
- DAS(Node-RED)·MQTT 토픽·FE 연동의 현장 판단 (BE 범위 밖 합의)

# 6. 기대 효과 및 의의

## 기대 효과

| 영역 | 효과 |
| --- | --- |
| 기획·문서 | AMR 도메인 조사·배경·비전 문서화 시간 단축, 발표·보고 초안 작성 부담 감소 |
| 설계 | API·계층 구조·TODO 기반 작업 분해로 설계 누락·구현 순서 혼선 완화 |
| 개발 | 보일러플레이트·CRUD·계층 코드 작성 속도 향상, BE 중심 구현·정합성 검토에 인력 집중 |
| 협업 | `AGENTS.md` 기반 AI 프롬프트·규칙 공유로 담당자별 편차 축소 |
| 품질 | 설계 문서 재입력 검토 + Copilot PR 리뷰로 jwt.secret 커밋, `node_modules` 추적, DB-BE 스키마 불일치 등 실수 조기 발견·수정 |

## 의의

- **제한된 기간·인원에서 "통합 관제" 수준의 산출물 달성**: 단일 화면이 아니라 실시간 관제, 비상 정지 흐름(FE-BE-DB-DAS), WebSocket·MQTT 연동까지 다루는 과제에서, AI가 반복·초안 작업을 담당하고 팀은 도메인 판단·명세 확정·검증에 집중할 수 있었다.
- **AI Assisted Development를 프로세스로 내재화**: 도구 나열이 아니라 "조사 → 초안 → 팀 재서술 → 설계 정합성 재검토 → TODO 순차 구현 → PR 리뷰"라는 검증 루프가 문서·`AGENTS.md`·`시행착오.md`로 남았다.
- **스마트팩토리·AMR 관제 도메인과의 정합**: AI는 일반적인 CRUD 예제가 아니라, 현장 페인포인트(연동 미비, 안전사고, 데드락 등)와 맞닿은 요구(통합 모니터링, 비상 제어, 환경·이상 감시)를 설계·구현 맥락에 반영하는 보조 수단으로 쓰였다.
- **향후 고도화의 기반 마련**: `고도화 비전.md`에 적힌 이기종 통합·예지보전·디지털 트윈 방향은 런타임 AI가 아니라, 이번에는 개발 과정 AI로 명세·코드·문서 품질을 끌어올려 다음 단계 기능 확장 시 재사용 가능한 자산(설계서, API, ADR, 온보딩)을 쌓았다.

## 한계 및 주의사항

- AI 출력은 **사실·버전·보안 설정을 보장하지 않는다**. 반드시 팀 검토·로컬 실행·PR 리뷰를 거친다.
- Copilot Review는 변경 파일 수·범위가 크면 거부될 수 있으므로, PR 단위를 작게 유지하고 `.gitignore`를 사전에 점검한다.
