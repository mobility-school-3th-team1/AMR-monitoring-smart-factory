# 설계-구현 정합성 검토

**작성일:** 2026-05-19  
**기준:** `docs/프로젝트 정의서.md`, `docs/API 정의.md`, `docs/화면 설계서.md`, `docs/데이터 스키마 설계.md`, `docs/ADR/`, `BE/`·`FE/`·`DB/` 코드 및 `BE/TODO.md`·`FE/TODO.md`

## 1. 검토 방법

| 우선순위 | 정의 | 본 문서에서의 조치 |
| --- | --- | --- |
| **1** | 설계와 구현이 일치 | 유지. 설명 부족 시 설계 문서 보충 |
| **2** | 구현됐으나 설계에 없음 | 설계 문서에 상세 기록 추가 |
| **3** | 설계만 있고 미구현 | 판단·삭제 보류. 1·2번 수정과 충돌하지 않는 범위에서만 보완 |
| **4** | 개요·발표 등 비개발 문서에만 존재 | 개발 범위 밖이면 해당 문서에서 삭제 |

**현재 스택 상태 (검증 기준일):**

- **BE:** Docker + H2 in-memory, Phase A REST·Phase B WebSocket(2종 이벤트) 구현 완료, Swagger UI(S-1~S-3) 완료
- **FE:** Vue 3 + Vite, 일부 화면 REST 연동, WebSocket·MQTT 비활성(`main.js` 주석)
- **DB:** `DB/init.sql` DDL·시드 존재, Node-RED 플로우·compose 미포함

## 5. 설계-구현 불일치 (1번 유지 전제下的 수정 필요)

우선순위 1「유지」 항목 중 **현재 코드가 어긋나는** 지점이다. 설계를 바꾸지 않고 구현·문서 중 한쪽을 맞춘다.

### 5.1 FE AMR `status` enum 불일치 (중요)

- **설계·BE:** `OPERATING`, `IDLE`, `CHARGING`, `ERROR`, `EMERGENCY_STOP`
- **FE `AmrListView`:** `STATUS_MAP` 키가 `running`·`waiting` 등 **소문자 UI용 값** → API 응답과 불일치 시 전부 `waiting`으로 분류될 수 있음
- **해결:** FE에서 `DashboardStatusNormalizer`와 동일 enum으로 매핑 후 UI 라벨만 변환. 화면 설계서 「AMR 운행 상태와 API 매핑」표를 FE 구현 체크리스트로 인용

### 5.2 환경 데이터 이중 경로

- **화면 설계서·API:** `GET /environment/areas/current`
- **BE TODO 합의:** 실시간 환경 = **FE ← MQTT ← DAS**, BE REST 보류
- **해결:** 3-API-01 보완과 함께, **SCR-01 ③의 단일 데이터 소스를 팀이 MQTT로 확정**한 뒤 API 명세에서 SCR 참조를 「MQTT(주)·REST(선택)」로 정리. 양쪽을 동시에 필수로 두지 않는다

### 5.3 `FE/PROGRESS.md` vs 실제

- PROGRESS는 WebSocket·MQTT·화면 구현 **완료**로 기술하나, `main.js`는 비활성이고 다수 뷰가 목업이다
- **해결:** PROGRESS를 **아카이브**하거나 FE TODO와 병합. 「완료」 표현 삭제(§4)

### 8.2 충돌 상세 및 확정 방향

#### C-P2-01 — 실시간 갱신 채널 (가장 큰 충돌)

| 영역 | P2 구현·기록 | 내용 |
| --- | --- | --- |
| **FE** | 2-FE-01, `main.js` | MQTT **비활성**. `DashboardView`·`AmrListView` **REST 폴링** (10s / 15s) |
| **BE** | 2-BE-06, Phase B | `WS /api/v1/stream` + `amrs.status.updated`·`dashboard.summary.updated` **구현 완료** |
| **BE TODO** | L21–22 | 텔레메트리(좌표·환경) = **FE←MQTT←DAS**. FE WS 연동은 **미착수** |
| **FE PROGRESS** | (P4 삭제 대상) | MQTT **완료**로 서술 → 실제와 반대 |

**모순:** BE는 「WS로 FE 갱신」을 전제로 문서화했고, FE는 「WS/MQTT 보류·REST 폴링」을 전제로 동작한다.

**확정 (FE 최우선):**

| 데이터 종류 | 시연 확정 채널 | BE·DAS 조치 |
| --- | --- | --- |
| 대시보드 KPI·AMR 운행 상태·알람·충전·작업 이력 | **REST 폴링** (화면별 주기는 C-P2-08에서 통일) | BE WebSocket은 **유지하되 FE 필수 아님**. 신규 FE 기능은 WS **강제 금지** |
| AMR 평면도 좌표·경로 애니메이션 | **향후 MQTT←DAS** (2-FE-01) | BE `amrs.position.updated` 스케줄 연출은 **구현하지 않음**(DAS·FE MQTT와 이중) |
| 비상 정지 후 DAS 시뮬 중단 | **MQTT publish** (활성화 시, ADR 순서) | BE `accepted` 후 REST/WS로 UI만 갱신 |

**문서화:** `docs/FE-DAS_MQTT_연동.md`(신규)에 「BE WS = 선택 소비, 시연 FE = REST 폴링」을 명시. `BE/TODO.md` L127 「REST 폴링 가능」을 **「시연 FE 기본 경로」**로 격상.

#### C-P2-02 — 환경 데이터 (SCR-01 ③)

| 영역 | 내용 |
| --- | --- |
| **FE** (2-FE-03) | `DashboardView` **정적 HTML** (REST·MQTT 미사용) |
| **BE** (12-F 보류) | `GET /environment/areas/current` **미구현**. 「실시간 = MQTT」 합의 |
| **DAS&DB** | `ENV_SENSOR` 시드 있음, **`ENV_SENSOR_LOG` 시드 없음** → REST 집계도 당장 빈약 |

**모순:** API·화면 설계는 BE REST를 가리키고, BE TODO는 MQTT, FE는 목업이다.

**확정:**

1. **FE:** 시연까지 **정적 목업 유지** 또는 DAS MQTT 연동 시 **구독으로 교체** (REST 연동은 2차).
2. **DAS&DB:** MQTT payload는 `AREA`·센서 타입(`TEMP`/`HUMIDITY`/`PARTICLE`)을 `init.sql`·API §2 예시와 **필드명 정합** (DAS&DB가 스키마 원본).
3. **BE:** `GET /environment/areas/current`는 **시연 필수 아님**. MySQL merge·로그 적재 후 **스냅샷/이력 API**로 재정의 (FE가 요청할 때만).

#### C-P2-09 — AMR `status` enum (FE ↔ BE)

| 영역 | 표기 |
| --- | --- |
| **BE** (2-BE-05) | API 응답 `OPERATING`·`IDLE`·`CHARGING`·`ERROR`·`EMERGENCY_STOP` |

**모순:** P2에서 BE는 「정규화 완료」, FE는 다른 키를 사용 → 연동 시 전부 `waiting` 처리 위험.

#### C-P2-10 — Refresh token (BE ↔ DAS&DB)

| 영역 | 내용 |
| --- | --- |
| **BE** (2-BE-03) | `InMemoryRefreshTokenStore` |
| **DAS&DB** | `REFRESH_TOKEN` 테이블 DDL·ERD |

**모순:** 스키마는 DB 영속, 시연 BE는 메모리.

**확정:** **DAS&DB** DDL·ERD **유지**(통합 시 기준). **BE** 시연은 인메모리 **허용** — 단, FE는 기존 `axios` refresh **유지**(단일 BE 인스턴스 전제). MySQL merge 시 **BE가 DDL 따름**(우선순위 DAS&DB > BE).

#### C-P2-11 — 런타임 DB H2 vs MySQL DDL

| 영역 | 내용 |
| --- | --- |
| **BE** (2-BE-02) | Docker **H2** `create-drop` |
| **DAS&DB** | `init.sql` **MySQL** DDL + 시드 |

**모순:** P2 문서에 「DB=MySQL」과 「시연=H2」가 동시에 쓰이면 FE·DAS가 어느 DB를 보라는지 혼란.

**확정:** **DAS&DB** `init.sql` = **물리·논리 스키마 원본**. **BE H2** = **시연 런타임 한정**(BE 문서·README에 명시). **FE**는 DB 종류 **비의존**(REST만). Node-RED·MySQL compose merge 전까지 DAS는 **MQTT로 FE에 직접** 공급하는 경로와 정합.

---

#### C-P2-12 — 비상 정지와 MQTT 비활성

| 영역 | 내용 |
| --- | --- |
| **FE** (2-FE-01) | `initMqtt()` **미호출**, `AmrDetailView` `alert()` 목업 |
| **BE** (2-BE-04) | `emergencyStop` **DB 반영 완료** |

**모순:** ADR상 FE는 `accepted` 후 MQTT인데, P2 FE는 MQTT 꺼짐 → **DB만 정지·DAS는 계속 움직일 수 있음**.

**확정 (FE):**

- **MQTT 비활성 기간:** UI는 **REST 폴링/수동 새로고침**으로 `EMERGENCY_STOP` 표시. DAS 미연동은 **시연 한계**로 문서화.
- **MQTT 활성화 후:** ADR 순서 **강제** (`accepted` → `publish`).
- **BE:** 동작 **유지**. DAS 정지 여부는 FE MQTT 책임.
